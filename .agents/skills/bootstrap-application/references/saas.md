# SaaS profile

Confirm the service's users, access model, registration/invitation policy, durable data,
tenant boundaries (if any), and first paid or unpaid journey. A typical SaaS applies the
database and authentication skills, adds reviewed migrations, and protects an app shell and
every server operation. The need for billing does not follow from the word “SaaS.”

Record verification/recovery and provisioning behavior before public launch. Test session
expiry/revocation and owner-scoped access. Add organizations, multi-tenancy, roles, OAuth,
billing, or an external API only when the actual requirements call for them; those need
their own explicit design and verification.
